## 7. 偏差与决策

1. **流程含「发起」节点**：6 条 BPMN 均为 start → userTask「发起」(assignee=${initiator}) → 审批(candidateGroups) → end；业务 submit 后发起人产生 1 条「发起」待办，需确认提交后进入审批（D33 驳回回发起节点之所需）。验收脚本与前端提示均按此语义。
2. **文档可见性**：非 ADMIN 可见 = 创建人 ∪（已发布/归档且 `coll_doc_perm` 命中）∪ 已通过借阅；ICP_MANAGER 无全量旁路，故其列表 12/40 属预期。
3. **借阅状态**：以 DDL 为准 0 申请中/1 已通过/2 已驳回/3 已归还（非文档最初写的 0/1/2）。
4. **公告范围编码**：`dept_scope` 存 `全公司` / `DEPT:2,3` / `ROLE:EMPLOYEE,AUDITOR`，API 返回 scope+scopeDeptIds+scopeRoles。
5. **日程取消=3**（2=已结束）；**消息提醒 type=3 + biz_type=REMIND**；**文档版本次版本+1**（V1.9→V1.10）。
6. **系统消息发送**：`ADMIN 或 collab:message:send`（原 AND 判定因 ADMIN 无该权限成为死接口，已修）。
7. **月历返回对象** `{month,items,total}`（非数组）。
8. **jjwt**：对 token 追加 1 字符仍校验通过，追加 5 字符才 401（已知限制，M3 安全加固项）。

## 8. 发现并修复的问题

| # | 问题 | 处理 |
| --- | --- | --- |
| 1 | `POST /messages` 40300（AND 判定 + ADMIN 无权限串 → 无人能发） | 后端改 `hasRole('ADMIN') or hasAuthority('collab:message:send')`，不改种子；Lead 复验 200 |
| 2 | 文档列表最初把 perm 行当「可见」放大范围 | 后端收紧为 owner ∪ 授权 ∪ 已通过借阅；ADMIN 全量 |
| 3 | 借阅审批在 Lead 脚本中失败 | 根因是流程「发起」节点；脚本改为发起人先确认提交再审批（非缺陷） |
| 4 | Lead 脚本 PowerShell 变量大小写不敏感：函数参数 `$b` 覆盖 `$Base` 导致 URI 解析失败 | 变量改名（教训：PS 变量大小写不敏感，勿用 $B/$b 同义名） |
| 5 | 消息字段名 `isRead` 误写（实际 `readFlag`） | 脚本改 `readFlag`；契约文档补字段名 |
| 6 | 文档列表断言 40 因前次上传变 41 | 脚本改 `-ge 40` 并注明（最终干净种子为 40） |

## 9. 遗留 / 已知限制

1. 消息仅「系统消息 + 任务提醒」两类；无聊天会话/群组（方案未要求，二期）。
2. 文档预览（PDF/Office 在线预览）未做，仅下载；方案标注「预览预留」。
3. 文档版本仅版本号+文件替换，无历史版本回看（二期）。
4. 日程无重复日程/提醒推送（站内提醒依赖消息中心，M2e 定时任务统一）。
5. SSE 为单实例内存连接注册（每用户 3 连接；多实例需 Redis 广播，二期）。
6. 文档删除为逻辑删除，物理文件保留（附件 GC 二期）。
7. jjwt 追加 1 字符仍通过校验（§7.8）；M3 安全加固清单已记录。
