## 2. 建设目标与范围（方案 §1）

**总目标**：面向单租户企业（预留多租户），以「制度—风险—控制矩阵—内控评价—缺陷整改」闭环为核心，融合审批流、协同任务、文档与消息、内控指标看板，提供组织权限/数据权限/审计/附件等基础能力，支持一键部署、可备份、可监控、可回滚。

**MVP 范围（方案 §1.2，七项一期全做）**：

1. 组织权限与 JWT 登录（部门/岗位/用户/角色/菜单/按钮，RBAC + 数据权限，登录安全策略，在线用户）
2. 流程引擎与表单/审批中心（BPMN 定义、表单绑定、待办/已办/抄送/催办、超时预警、历史留痕）
3. 制度库、风险库、控制矩阵（分类/版本/生效、风险等级与评分、风险—控制点—制度—流程—岗位关联）
4. 内控评价、缺陷整改闭环（评价计划/任务/评分/底稿、缺陷分级、整改任务与证据、复核关闭）
5. 协同任务、文档中心、公告消息、日程（任务/子任务/优先级/提醒、目录与权限、站内信）
6. 报表看板与审计日志（内控覆盖率/风险分布/整改完成率/流程耗时、预警、操作/登录/变更审计）
7. Docker Compose 一键部署（Compose 文件 + 本地一键脚本 + 备份脚本）

**二期范围（一期不做）**：合同/采购/费用插件、低代码表单设计器、ES 全文检索、移动端 App、K8s/Helm 实机部署、多租户实装。

## 4. 角色与数据权限（6 角色）

| 角色 | 主要职责 | 数据范围 |
| --- | --- | --- |
| 系统管理员 | 组织/用户/角色/菜单/字典/参数/附件/定时任务/日志 | 全量 |
| 内控管理员 | 制度/风险/控制矩阵/评价/缺陷/整改的配置、推进与复核 | 全量（内控域） |
| 部门负责人 | 本部门审批、整改推进、部门任务与看板 | 本部门及下级 |
| 普通员工 | 发起审批、我的任务、文档、公告、日程、消息 | 本人 |
| 审计员 | 审计日志、登录日志、流程留痕、评价底稿只读 | 全量只读（审计域） |
| 管理层 | 经营/内控看板与报表只读 | 全量只读（看板域） |

数据权限维度：本人 / 本部门 / 本部门及下级（自定义部门范围暂缓，二期）。前端隐藏 + 后端数据权限拦截器兜底，每角色至少 1 条允许 + 1 条拒绝用例。

## 5. 核心业务闭环（演示主线）

```text
制度发布(审批) → 风险登记 → 控制矩阵关联 → 评价计划/任务/评分/底稿
      → 缺陷登记(分级) → 整改任务(证据上传) → 复核关闭 → 看板与预警
```

审批流贯穿：制度发布、缺陷整改、评价计划、文档借阅、采购申请、用印申请共 6 条内置流程；协同侧提供任务、文档、公告、消息、日程支撑。

## 7. 关键约束

- 《软著 Demo 手册》为私有资料，不复制进仓库、不上传远端；仓库内只放项目自身文档与代码。

- 不修改/停用现有 MySQL80 服务（3306）；项目使用独立实例 3307（数据目录 `.runtime/mysql`）。
- 画像、角色、字段、流程、菜单、字典等动态项来自本方案与画像，不套用其他项目。
- Windows + PowerShell 7 环境；源码 UTF-8；中文路径可接受。
