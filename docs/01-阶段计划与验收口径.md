## 1. M1 契约与数据底座

**交付物**

- `docs/03-接口契约.md`：REST 规范、统一返回、分页、鉴权、错误码、按模块接口清单（字段级请求/响应）、状态机与枚举
- `docs/04-数据模型与种子.md`：表清单（字段/类型/索引/外键/统一字段）、Flyway 版本策略、种子规模与自洽规则
- `docs/05-权限矩阵.md`：角色 × 菜单/按钮/接口/数据范围，附「允许/拒绝」用例编号
- 后端骨架：Spring Boot 工程、Flyway、MyBatis-Plus、Security + JWT、统一响应/异常/审计切面、OpenAPI
- 前端骨架：Vue3 + Vite + Element Plus + Pinia + Router、登录页、主框架（侧栏/顶栏/面包屑/标签页）、动态路由与按钮权限
- 数据库：项目内 MySQL 8.0.46 实例（3307）、库 `icp_platform`、账号 `icp_app`
- 种子数据（示例规模，M1 冻结；M2a 追加定时任务菜单与系统管理按钮后为 105/281）：部门 8 / 岗位 6 / 用户 30 / 角色 6 / 菜单+按钮 105（6 目录 + 40 C + 59 F） / 制度 40（分类 12）/ 风险 40 / 控制点 60 / 控制矩阵 60 / 评价计划 4 / 评价任务 20 / 底稿 20 / 缺陷 30 / 整改 25 / 流程定义 6 / 任务 80 / 文档 40 / 公告 12 / 日程 20 / 消息 60 / 字典 20 / 参数 15 / 日志 300
- 流程运行数据（流程实例 60 / 待办 40 / 历史留痕）不写入 Flyway SQL（ACT_* 由 Flowable 自建，H2/MySQL 方言差异大且需引擎 API），改由 M2c `scripts/seed-flow.ps1` 调用流程 API 生成；**M1 只校验流程定义与表单静态种子**（`wf_process_meta` 6 条、`wf_form` 不少于 6 条）及 `wf_*` 表结构，流程实例/待办规模在 M2c 验收报告中记录。

**验收口径（M1 冻结）**

1. `scripts/db-reset.ps1`：停实例 → 重建库 → Flyway migrate → 种子 → `db-validate`，全绿且重复执行幂等
2. `db-validate` 校验：金额/数量自洽、状态机可达、外键无孤儿、日期顺序、权限矩阵完整性；失败即初始化失败
3. `scripts/build-backend.ps1`（`mvn -q clean verify`）零错误；`GET /actuator/health` = `UP`
4. 前端 `npm run build` 零错误；登录 → 菜单 → 角色切换冒烟通过
5. 契约字段与 DDL 一致（脚本比对）；提交 hash 写入 M1 报告（`docs/06-M1-验收报告.md`）

## 2. M2 业务实现（5 个批次，可并行分派）

**M2a 组织权限与审计**：部门树 / 岗位 / 用户 CRUD、角色/菜单/按钮、用户角色、角色菜单、数据权限（本人/本部门/本部门及下级）；登录（JWT access + refresh）、密码策略、失败锁定、在线用户；操作日志、登录日志、关键表变更审计。验收：组织/用户/角色/登录/越权拒绝 API 用例；菜单按角色动态渲染；日志落库。

**M2a 验收用例清单（Lead 冻结，`scripts/test-api-m2a.ps1` 与验收报告逐条对应）**：

| 编号 | 用例 | 期望 |
| --- | --- | --- |
| A01 | admin 登录 | code=0，返回 access/refresh/user/roles/permissions/menus |
| A02 | 错误密码登录 | code=40101，提示「用户名或密码错误」 |
| A03 | 连续 5 次错误密码 | 第 5 次起 code=40102 且 data 含剩余秒数；正确密码在锁定期内仍 40102 |
| A04 | 密码策略 | 新密码长度/复杂度不满足时 code=40000 |
| A05 | refresh 刷新 | 新 accessToken 可用；旧 refresh 仍按 7 天有效 |
| A06 | logout 后使用旧 token | code=40100/40103（失效），在线会话移除 |
| A07 | 修改本人密码 | 旧密码正确→code=0；旧密码错误→40000；改后旧密码登录失败 |
| A08 | 部门树/列表/新增/编辑/删除 | CRUD 成功；删除有子部门或用户的部门→40000 并提示原因 |
| A09 | 岗位分页/新增/编辑/删除 | CRUD 成功；分页 total 正确 |
| A10 | 用户列表筛选 | deptId/keyword/status 过滤结果正确（对照种子） |
| A11 | 用户新增（含角色） | code=0；重复用户名→40000；密码入库为 BCrypt（不可见明文） |
| A12 | 用户编辑/状态/重置密码 | 状态切换生效；重置后新密码可登录、旧密码失败 |
| A13 | 用户删除 | 逻辑删除后列表不可见、详情 40400；关联 user_role 失效 |
| A14 | 角色 CRUD | 新增角色可授权；内置 6 角色不可删除 |
| A15 | 角色菜单授权 | 保存后该角色重新登录，menus/permissions 按新授权返回（含祖先节点、无孤儿） |
| A16 | 菜单树/CRUD | 树形返回；删除有子节点或已被引用的菜单→40000 |
| A17 | 字典类型/项 CRUD | 项按 type 查询正确 |
| A18 | 参数修改 | 只改值生效；get 返回新值 |
| A19 | 定时任务列表/状态/手动触发 | 状态流转成功；手动触发记录 oper_log（扫描 M2e 接入） |
| A20 | 附件上传/元数据/下载 | 上传返回 fileId；白名单外类型→40000；下载内容一致 |
| A21 | 数据权限：admin（4） | 用户列表可见 30 人 |
| A22 | 数据权限：临时角色 `dataScope=2`（本部门）+ 临时用户（真实库建/删） | 用户列表仅本部门用户（= 部门人数 + 1）；dept01 因 seed 中仅 ADMIN 有 `system:user:list` 不适用本用例，改用临时角色验证（实现见 `.smoke-m2a/verify-m2a.ps1` §3） |
| A23 | 数据权限：staff01（1 本人） | 用户列表仅本人（1 条） |
| A24 | 越权详情 | staff01 查他人详情→40300；管理接口→40300 |
| A25 | 权限拒绝：icpadmin 调 /users 新增 | 40300（无 system:user:add） |
| A26 | 权限拒绝：auditor 调用户新增 | 40300；auditor 可查日志 |
| A27 | 操作日志落库 | 新增/编辑后 sys_oper_log 出现对应记录（含 traceId、耗时、IP） |
| A28 | 登录日志落库 | 成功/失败均落 sys_login_log，含原因 |
| A29 | 变更审计 | 修改用户后 `/logs/changes?bizType=sys_user&bizId=` 返回 before/after，密码字段脱敏 |
| A30 | traceId 串联 | `/logs/trace/{traceId}` 返回同一次请求的日志 |
