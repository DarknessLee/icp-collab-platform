> 与 `docs/03-接口契约.md`、`docs/04-数据模型与种子.md` 配套；`sys_menu.perms` 即接口权限标识，前端 `v-perm` 与后端 `@PreAuthorize` 使用同一字符串。

## 1. 角色定义（sys_role）

M2b 落地说明（2026-11-03）：`ADMIN` 对内控业务**严格只读**（仅 `icp:*:list/get` 与 `icp:matrix:coverage`），业务写权限只在 `ICP_MANAGER`（全量）与 `DEPT_MANAGER`（本部门执行类）手中，体现「系统管理员不碰业务数据」的三权分立；后端 `@PreAuthorize` 已按此校验，admin 调内控写接口返回 40300，前端对 admin 隐藏内控写按钮。

M2c 落地说明（2026-11-03，D30–D35）：
- `ADMIN` 流程侧改为**监控 + 流程定义只读**（`workflow:monitor:view`、`workflow:process:list`、`workflow:instance:get`、`workflow:purchase:get`/`seal:get`/`borrow:get`），**不做审批动作**（无 `workflow:task:approve/reject/urge`）。
- 「待办/已办/我发起」6 角色全量可见（数据按 §4 过滤）；审批动作（approve/reject/urge）只给 `ICP_MANAGER`、`DEPT_MANAGER`、`EMPLOYEE`、`MANAGEMENT`（`ADMIN`/`AUDITOR` 不给）。
- 采购/用印/借阅**创建**（`workflow:purchase:add`、`workflow:seal:add`、`workflow:borrow:add`）给 `ICP_MANAGER`、`DEPT_MANAGER`、`EMPLOYEE`；`AUDITOR`/`MANAGEMENT` 只读，`ADMIN` 只读。
- 待办办理人由 Flowable 任务候选组（角色编码）二次校验，因此即使有按钮权限，非候选组用户调 approve/reject 仍 40300（C05 用例）。
- 种子行数（sys_menu / sys_role_menu）在 M2c 种子定稿后同步到 docs/04 §6.3 与 docs/01。

M2d 落地说明（2026-11-03，D36–D38）：`ADMIN` 对协同运营**全部只读**（16 个 collab 只读权限，无 add/edit/delete/publish/complete/remind 等写按钮）；`ICP_MANAGER` 协同全量（43）、`DEPT_MANAGER` 部门写（42）、`EMPLOYEE` 本人（26）、`AUDITOR`/`MANAGEMENT` 只读（各 16）。文档中心可见性=创建人 ∪ 授权命中（`coll_doc_perm`）∪ 已通过借阅，ADMIN 全量；下载另需 `collab:doc:download` + 文档级权限。任务提醒/催办写站内消息（`message_type=3`）；系统消息发送=ADMIN 或 `collab:message:send`。详见 §9。

## 4. 数据权限规则

### 4.1 统一规则

- 由 `DataScopeInterceptor`（MyBatis-Plus 内嵌拦截器）在 SQL 层追加条件，业务代码不得手写数据范围判断。
- 生效对象：`icp_policy`、`icp_risk`、`icp_control`、`icp_evaluation`、`icp_evaluation_task`、`icp_defect`、`icp_rectify`、`wf_purchase`、`wf_seal`、`coll_task`、`coll_doc`；`sys_*` 配置类表不参与。
- 判定字段：`dept_id`（业务归属部门）+ `create_by`/`assignee_id`（本人维度）。

| data_scope | 追加条件（伪 SQL） |
| --- | --- |
| 4 全部 | 无条件 |
| 3 本部门及下级 | `dept_id IN (SELECT id FROM sys_dept WHERE id = :deptId OR FIND_IN_SET(:deptId, ancestors))` |
| 1 本人 | `(create_by = :userId OR assignee_id = :userId)` |

- 多角色取「并集」（任一角色允许即允许），实现时取最宽范围。
- 越权访问统一返回 `40300`；列表过滤后自然为空。
- 管理端/流程引擎内部（如定时任务、系统初始化）通过 `DataScope.ignore()` 显式绕过，需审计注释。

### 4.2 流程参与人例外

流程任务的可见性不只看部门：待办/已办按 Flowable 任务候选人/办理人判定；节点上配置的「部门负责人」「管理层」通过候选人组 `ROLE_DEPT_MANAGER` / `ROLE_MANAGEMENT` 解析，解析逻辑在 `WorkflowUserResolver`（M2c）。

## 5. 前端权限实现

1. 登录响应返回 `permissions`+`menus`；Pinia 存 `userStore`，刷新页面先 `/auth/me` 恢复。
2. 菜单：后端按角色返回树，前端只渲染返回的菜单（前端不硬编码菜单权限）。
3. 按钮：`v-perm="'icp:policy:publish'"`，无权限时移除 DOM 或禁用；**仅为体验优化，后端必须独立校验**。
4. 路由守卫：未登录跳 `/login?redirect=`；无菜单路由跳 `/403`；直接输入越权 URL 亦由后端 403 兜底。
5. 401 自动尝试 refresh 一次，失败清 token 跳登录。

## 7. 与接口契约的对应关系

- 每个接口在 `docs/03` 中声明的权限，必须在本文件 §3 存在同名 `perms`；M1 验收命令 `scripts/verify-m1.ps1`（或等价校验）检查：`sys_menu.perms` 去重集合 ⊇ 后端 `@PreAuthorize` 使用的标识集合。
- 角色菜单初始化由 V2__seed_base.sql 写入 `sys_role_menu`，M1 验证脚本抽查 6 角色各 1 条允许/1 条拒绝。
