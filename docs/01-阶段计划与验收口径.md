## 1. M1 契约与数据底座

**交付物**

- `docs/03-接口契约.md`：REST 规范、统一返回、分页、鉴权、错误码、按模块接口清单（字段级请求/响应）、状态机与枚举
- `docs/04-数据模型与种子.md`：表清单（字段/类型/索引/外键/统一字段）、Flyway 版本策略、种子规模与自洽规则
- `docs/05-权限矩阵.md`：角色 × 菜单/按钮/接口/数据范围，附「允许/拒绝」用例编号
- 后端骨架：Spring Boot 工程、Flyway、MyBatis-Plus、Security + JWT、统一响应/异常/审计切面、OpenAPI
- 前端骨架：Vue3 + Vite + Element Plus + Pinia + Router、登录页、主框架（侧栏/顶栏/面包屑/标签页）、动态路由与按钮权限
- 数据库：项目内 MySQL 8.0 实例（3307，本地脚本兼容 MySQL 5.7+）、库 `icp_platform`、账号 `icp_app`
- 种子数据（数据规模，M1 冻结；M2a 追加定时任务按钮 → 105/281；M2b 追加内控 38 个按钮并撤回 ADMIN 内控写授权 → 143 / 385；M2c 追加文档借阅菜单与 5 个流程按钮 → 149 / 431；M2d 追加协同 30 个按钮 → **179 / 540**，参数 16）：部门 8 / 岗位 6 / 用户 30 / 角色 6 / 菜单+按钮 179（6 目录 + 41 C + 132 F） / 制度 40（分类 12）/ 风险 40 / 控制点 60 / 控制矩阵 60 / 评价计划 4 / 评价任务 20 / 底稿 20 / 缺陷 30 / 整改 25 / 流程定义 6 / 任务 80 / 文档 40 / 公告 12 / 日程 20 / 消息 60 / 字典 20 / 参数 16 / 日志 300
- 流程运行数据（流程实例 60 / 待办 40 / 历史留痕）不写入 Flyway SQL（ACT_* 由 Flowable 自建，H2/MySQL 方言差异大且需引擎 API），改由 M2c `scripts/seed-flow.ps1` 调用流程 API 生成；**M1 只校验流程定义与表单静态种子**（`wf_process_meta` 6 条、`wf_form` 不少于 6 条）及 `wf_*` 表结构，流程实例/待办规模在 M2c 验收报告中记录。

**验收口径（M1 冻结）**

1. `scripts/db-reset.ps1`：停实例 → 重建库 → Flyway migrate → 种子 → `db-validate`，全绿且重复执行幂等
2. `db-validate` 校验：金额/数量自洽、状态机可达、外键无孤儿、日期顺序、权限矩阵完整性；失败即初始化失败
3. `scripts/build-backend.ps1`（`mvn -q clean verify`）零错误；`GET /actuator/health` = `UP`
4. 前端 `npm run build` 零错误；登录 → 菜单 → 角色切换冒烟通过
5. 契约字段与 DDL 一致（脚本比对）；提交 hash 写入 M1 报告（`docs/06-M1-验收报告.md`）
