# 04 · 数据模型与种子数据（M1 契约）

> 适用范围：M1 冻结；M2 如需加字段必须走 Flyway 新版本并同步本文与 `docs/03`。
> 权威 DDL 位置：`backend/src/main/resources/db/migration/V1__schema.sql`（由本文定义生成）、`V2__seed_base.sql`、`V3__seed_business.sql`。
> 数据库：MySQL 8.0.46，库 `icp_platform`（utf8mb4 / utf8mb4_general_ci，`lower_case_table_names=1`），账号 `icp_app`。

## 1. 设计约定

| 约定 | 内容 |
| --- | --- |
| 表名前缀 | `sys_` 系统、`icp_` 内控、`wf_` 流程业务、`coll_` 协同；Flowable 引擎表 `ACT_*` 由引擎自建，**不写入 Flyway** |
| 主键 | `id BIGINT NOT NULL AUTO_INCREMENT`（Flowable 表除外） |
| 统一字段（所有业务表） | `tenant_id BIGINT NOT NULL DEFAULT 0`（多租户预留）、`create_by BIGINT`、`create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP`、`update_by BIGINT`、`update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`、`deleted TINYINT NOT NULL DEFAULT 0`（逻辑删除） |
| 时间 | `DATETIME` 存本地时间（+08:00），日期语义用 `DATE`；不存时区后缀 |
| 金额 | `DECIMAL(14,2)`；禁止 float/double；单位：元 |
| 比例/评分 | `DECIMAL(5,2)`（0.00–100.00） |
| 布尔 | `TINYINT`，0/1，字段名用 `xxx_flag` 或 `status` 语义另定 |
| 枚举 | `TINYINT` + 数字含义写入本文与 `sys_dict_data`；接口层出参同时给 `code` 与 `label` |
| 长文本 | 富文本/HTML 用 `LONGTEXT`；JSON（表单 schema）用 `JSON` 类型 |
| 编码 | 业务编号唯一索引，规则见 §5 |
| 审计留痕 | 操作日志 `sys_oper_log`；登录日志 `sys_login_log`；**数据变更审计复用 `sys_oper_log`**：`action=CHANGE`、`bizType=表名`、`bizId=主键`，`request_param` 存脱敏后的 `{before,after}` JSON（密码/密钥类字段以 `***` 替换，超长截断），M2a 起生效（DECISIONS D26，不新增表） |
| 命名 | 表/字段 snake_case；索引 `idx_表_字段`；唯一索引 `uk_表_字段` |
| 字符集 | 表级 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci` |
| 逻辑删除 | MyBatis-Plus `@TableLogic`；查询默认过滤 `deleted=0`；唯一索引需容忍历史删除（Demo 以业务编码唯一 + 不物理删除为准） |

## 2. 迁移策略

| 版本 | 内容 | 说明 |
| --- | --- | --- |
| `V1__schema.sql` | 全部业务表 DDL（本文件 §3） | 只建表与索引，不插数据 |
| `V2__seed_base.sql` | 系统域种子：部门/岗位/用户/角色/菜单/用户角色/角色菜单/字典/参数 | 固定 id，幂等（重建库执行） |
| `V3__seed_business.sql` | 业务种子：制度/风险/控制/矩阵/评价/缺陷/整改/任务/文档/公告/日程/消息/采购/用印/日志 | 依赖 V2 的 id |
| `V4+` | M2 起新增 | 每次变更同步本文与 `docs/03` |

- 初始化链路：`scripts/db-reset.ps1` = 停实例 → `DROP DATABASE` → 建库 `icp_platform` → 建账号 `icp_app` → Flyway migrate → `db-validate`。**db-validate 失败即视为初始化失败**。
- Flyway 参数：`baseline-on-migrate=true`、`out-of-order=false`、`validate-on-migrate=true`；迁移脚本只增不改。
- Flowable 表：`flowable.database-schema-update=true`，引擎首次启动建 `ACT_*`；重建库后由后端启动重建。
- 统计口径所需视图/索引随 M2e 增加，需新 Flyway 版本。

## 4. 状态机与枚举

| 对象 | 状态流转 | 约束 |
| --- | --- | --- |
| 制度 `icp_policy.status` | 0 草稿 → 1 审批中 → 2 已生效 → 3 已废止；2 → 4 已过期（按 `expire_date` 定时置位） | 生效必有 `effective_date` 与 `publish_time`；审批驳回回 0 并留痕；同一 `policy_code` 版本递增 |
| 风险 `icp_risk` | 1 启用 ⇄ 0 停用 | `risk_score = probability × impact`；等级默认 高(≥15)/中(8–14)/低(≤7) |
| 评价计划 `icp_evaluation.status` | 0 草稿 → 1 审批中 → 2 进行中 → 3 已完成 → 4 已关闭；驳回回 0 | 审批通过生成评价任务；`start_date ≤ end_date` |
| 评价任务 `icp_evaluation_task.status` | 0 待评价 → 1 进行中 → 2 已完成；`due_date < 今天` 且未完成 → 3 已逾期 | 完成必有 `score`、`conclusion`、底稿 ≥1 |
| 缺陷 `icp_defect.status` | 0 已登记 → 1 整改中 → 2 待复核 → 3 已关闭；2 复核驳回 → 1 | 关闭必有通过（status=2）的整改记录且 `close_time` 非空 |
| 整改 `icp_rectify.status` | 0 待整改 → 1 待复核 → 2 已通过 → 4 已关闭；1 复核驳回 → 3 已驳回 → 0 | `finish_date ≥ deadline` 视为逾期，报告标注；通过必有 `review_user_id`、`review_time` |
| 任务 `coll_task.status` | 0 待办 → 1 进行中 → 2 已完成 / 3 已取消 | 完成必有 `actual_end` 且 `progress=100`；逾期 = `plan_end < 今天` 且未完成 |
| 文档 `coll_doc.status` | 0 草稿 → 1 已发布 → 2 已归档 | 发布后版本号递增；下载计 `download_count` |
| 公告 `coll_notice.status` | 0 草稿 → 1 已发布 → 2 已关闭 | 发布必有 `publish_time`；关闭后不可见（详情可查） |
| 会议纪要 `coll_meeting.status` | 0 待召开 → 1 已召开（录入纪要即置 1）/ 2 已取消 | 已取消不可再编辑（40001）；会议编号 `meeting_no` 唯一，自动生成取全表 MAX（含逻辑删除行） |
| 采购/用印 | 0 草稿 → 1 审批中 → 2 已通过 / 3 已驳回；采购 2 → 4 已完成 | 审批结果与 Flowable 实例状态一致 |
| 流程实例 `wf_business_link.status` | 0 运行中 → 1 已通过 / 2 已驳回 / 3 已撤回 | 与 Flowable 历史状态一致 |
