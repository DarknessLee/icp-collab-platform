## 3. 按钮权限标识（sys_menu.perms）

命名规范：`模块:资源:动作`；动作集合 `list/get/add/edit/delete/publish/submit/approve/export/view/audit/monitor`。

| 模块 | 权限标识 |
| --- | --- |
| 组织 | `system:dept:list/add/edit/delete`、`system:post:*`、`system:user:list/add/edit/delete/reset/status`、`system:role:list/add/edit/delete/menu`、`system:menu:list/add/edit/delete`、`system:dict:*`、`system:config:list/edit`、`system:job:list/edit/run` |
| 日志 | `system:log:oper`、`system:log:login`、`system:log:change`、`audit:log:view` |

## 4. 数据权限规则

### 4.1 统一规则

- 由 `DataScopeInterceptor`（MyBatis-Plus 内嵌拦截器）在 SQL 层追加条件，业务代码不得手写数据范围判断。
- 生效对象：`icp_policy`、`icp_risk`、`icp_control`、`icp_evaluation`、`icp_evaluation_task`、`icp_defect`、`icp_rectify`、`wf_purchase`、`wf_seal`、`coll_task`、`coll_doc`；`sys_*` 配置类表不参与。
- 判定字段：`dept_id`（业务归属部门）+ `create_by`/`assignee_id`（本人维度）。

| data_scope | 追加条件（伪 SQL） |
| --- | --- |
| 4 全部 | 无条件 |
| 3 本部门及下级 | `dept_id IN (SELECT id FROM sys_dept WHERE id = :deptId OR FIND_IN_SET(:deptId, ancestors))` |
| 1 本人 | `(create_by = :userId OR assignee_id = :userId)` |

- 多角色取「并集」（任一角色允许即允许），实现时取最宽范围。
- 越权访问统一返回 `40300`；列表过滤后自然为空。
- 管理端/流程引擎内部（如定时任务、系统初始化）通过 `DataScope.ignore()` 显式绕过，需审计注释。

### 4.2 流程参与人例外

流程任务的可见性不只看部门：待办/已办按 Flowable 任务候选人/办理人判定；节点上配置的「部门负责人」「管理层」通过候选人组 `ROLE_DEPT_MANAGER` / `ROLE_MANAGEMENT` 解析，解析逻辑在 `WorkflowUserResolver`（M2c）。

## 5. 前端权限实现

1. 登录响应返回 `permissions`+`menus`；Pinia 存 `userStore`，刷新页面先 `/auth/me` 恢复。
2. 菜单：后端按角色返回树，前端只渲染返回的菜单（前端不硬编码菜单权限）。
3. 按钮：`v-perm="'icp:policy:publish'"`，无权限时移除 DOM 或禁用；**仅为体验优化，后端必须独立校验**。
4. 路由守卫：未登录跳 `/login?redirect=`；无菜单路由跳 `/403`；直接输入越权 URL 亦由后端 403 兜底。
5. 401 自动尝试 refresh 一次，失败清 token 跳登录。

## 7. 与接口契约的对应关系

- 每个接口在 `docs/03` 中声明的权限，必须在本文件 §3 存在同名 `perms`；M1 验收命令 `scripts/verify-m1.ps1`（或等价校验）检查：`sys_menu.perms` 去重集合 ⊇ 后端 `@PreAuthorize` 使用的标识集合。
- 角色菜单初始化由 V2__seed_base.sql 写入 `sys_role_menu`，M1 验证脚本抽查 6 角色各 1 条允许/1 条拒绝。
