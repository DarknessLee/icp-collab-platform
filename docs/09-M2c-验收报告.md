## 6. 偏差与口径（已接受并写入文档）

1. **D28 过渡消除**：`POST /policies|evaluations|rectifies/{id}/submit` 现返回 `{pendingWorkflow:false, processInstanceId, taskId, businessNo}`，由引擎回调推进业务状态（docs/03 §5.1 ⑩）。
2. **驳回语义**：统一回发起节点而非上一节点；`resubmit` 复用同实例；重提后任务落到**首个审批节点候选组**而非发起人（D33 实现语义，验收按候选组查任务）。
3. **超时**：`workflow.timeout.hours=48` 入 `sys_config`，monitor 查询期计算；验收用 `timeoutHours=0/1` 覆盖（不等待真实 48h）。
4. **实例分布**：D31 原写「约 30 running/30 completed」，为同时满足 40 待办 + 20 催办，定稿为 **40 running / 20 completed**（seed-flow 40 条 running 各留 1 待办）。docs/03 §5.1 ⑪ 已同步。
5. **BPMN 布局**：BPMN XML 未含 DI 坐标，前端渲染时自动生成水平布局（fit 失败回退 1:1）。
6. **表单**：待办 formSchema 为通用 `title/reason`，业务字段从 formData/business 合并展示；不实现在线表单设计器（D31）。
7. **管理端只读**：ADMIN 无审批/创建权限（三权分立），仅只读监控/定义/实例/单据。

## 8. 遗留与已知限制

1. BPMN 均为「发起 → 一级审批 → 结束」，未做多级/会签/加签/转办/委托/自由跳转（二期）。
2. 无在线流程设计器与在线表单设计器（classpath 部署 + 通用表单，D31）。
3. 抄送无独立页面，仅落 `coll_message(type=CC)`；催办管理页 `visible=0`。
4. 流程实例删除/挂起/激活、流程变量审计页未做。
5. seed-flow 生成后业务单据总数会高于种子基线（采购 34/用印 22/借阅 18），核对时以「60 实例/40 待办/20 催办」为准。
6. M2b 遗留限制延续（矩阵唯一键与逻辑删除、无导出接口等，见 docs/08 §8）。
