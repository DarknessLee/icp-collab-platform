## 3. 关键数据事实（重建库后实测）

- 种子：`sys_menu 105`（6 目录 + 40 C + 59 F）、`sys_role_menu 281`（仅 ADMIN 281）、`sys_user_role 30`、`sys_user 30`、`sys_role 6`；`sys_config` 含 `sys.upload.maxSize=20`、`sys.login.maxFail=5`、`sys.login.lockMinutes=15`。
- 上传限制：20MB（`sys.upload.maxSize` 驱动，前后端同值）；21MB 文件 → `41300`；`.txt/.bin` → `41300「不支持的文件类型」`；合法 pdf → `code=0` + `GET /files/{id}/download` 200。
- 审计：写操作全部落 `sys_oper_log`；`/logs/changes` 返回 `action=CHANGE` 行（`bizType/bizId/params，password/secret/token 脱敏`）；登录成功/失败落 `sys_login_log`。
- 在线会话：`GET /auth/online` 列出 `jti/username/ip/loginTime/lastActive`；`DELETE /auth/online/{jti}` 后该 token 立即 401；重启清空（进程内注册表，D25）。
- 错误码：`40000/40001/40101/40102/40400/41300` 均 HTTP 200 + 业务码；`40100/40103→401`；`40300→403`；`50000→500`（`GlobalExceptionHandler` 统一）。
- 逻辑删除恢复语义（M2a 新增）：命中唯一键的历史删除行时复用 id 并全量覆盖请求字段；用户恢复会重建 `sys_user_role`；角色恢复会清空旧 `sys_role_menu`。

## 7. 本阶段发现并修复的缺陷（记录）

1. **dept_code / post_code 缺失导致新增 500**：改为自动生成（D0001/P001……）+ 唯一冲突恢复旧行；NOT NULL 兜底统一转 40000/40002，不再 500。
2. **登录权限树缓存未失效**：`auth:menus:<roleIds>` TTL 300s，角色/菜单变更后仍返回旧权限（A22 偶发 403 的根因）；已加 `CacheService.evictByPrefix` 并在 Role/Menu 写路径失效。
3. **逻辑删除恢复不完整**：恢复用户未重建角色关联、`gender=null` 违反 NOT NULL；恢复角色带旧授权；均已修复并有单测。
4. **后端进程管理**：`start-backend.ps1` 记录的 pid 是 cmd 启动器，旧 JVM 长期占用 8080 导致「上传 21MB 仍 code=0」的假象；改为 netstat 解析真实监听 pid + 兜底 kill。
5. **PS5.1 脚本编码陷阱**：UTF-8 无 BOM 的中文注释在 PS5.1 下吞换行，导致断言随机取错响应；验收脚本一律纯 ASCII。

## 8. 遗留与已知限制（不阻塞 M2a 验收）

1. 在线会话为进程内注册表，后端重启后清空；M4 若需持久化再评估（当前 Demo 可接受）。
2. `POST /jobs/{id}/run` 仅记录并返回提示，不接真实调度；调度器能力留 M2e。
3. 附件接口 M2a 仅要求登录（无独立权限位），业务下载控制在 M2b–M2d 各自接口叠加。
4. 字典类型删除在 M2a 末尾补齐，验收报告与 `docs/03` 同步记录。
5. `GET /files/{id}/preview` 对图片/PDF 返回内容流，Office 预览留 M4 文档中心。
