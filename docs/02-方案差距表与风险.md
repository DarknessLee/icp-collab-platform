## 3. 假设（方案未写明，先按此执行，用户可否决）

- A1 软件名称 = 方案标题「企业内控与协同运营管理平台」V1.0；工程名 `icp-collab-platform`
- A2 一期按方案 §1.2 七项全做，二期功能不做
- A3 产品形态 B/S，HTTP 本地访问；HTTPS 由生产 Nginx 承担，Demo 不做
- A4 演示规模：30 用户 / 6 角色 / 8 部门；不追求真实并发
- A5 企业、组织、人员、制度/风险编号均为虚构但合规自洽的 Mock，不出现真实企业/个人信息
- A6 时间与金额自洽：制度生效日期、评价周期、整改期限、流程耗时符合业务顺序
- A7 附件样例为 PDF/图片/Word 等本地文件；单文件 ≤ 20MB，类型白名单
- A8 演示账号统一密码（BCrypt 存储），登录页明示演示用途；密码策略可配置
- A9 流程超时阈值可配置（默认 24/48 小时），定时扫描 5 分钟一次
- A10 看板数据直接 SQL 聚合，不做数据仓库/预计算
- A11 前端 PC 最小宽度 1280，≥768 响应式降级；不保证手机完整交互
- A12 Docker Compose 仅交付文件不实测；本机以 `start-local.ps1` 验收
- A13 日志/审计留存 Demo 30 天，配置化
- A14 接口统一 `/api/v1`、统一返回 `{code,message,data,traceId}`、分页 `pageNum/pageSize`

## 4. 风险清单

| 风险 | 概率/影响 | 应对 |
| --- | --- | --- |
| Flowable 7 与 Spring Boot 3 / Java 21 兼容与调试成本 | 中 / 高 | M1 先做 1 条流程最小 spike 再批量；不合规则切轻量引擎（Q2） |

| 截图不新鲜（与最终 UI/数据不一致） | 高 / 中 | M3 用最终 UI + 最终种子统一重拍并记录 URL/时间 |

## 5. 待确认问题（Q1–Q5）

- **Q1 技术栈底线**：确认后端为真实 Java / Spring Boot + MySQL 8；Redis/MinIO 以进程内/本地存储替代并保留接口；Docker Compose 仅交付文件、不本机实测。若必须真实跑 Compose，需要安装 Docker Desktop/WSL2（本机当前无 Docker）。
- **Q2 流程引擎**：真实 Flowable 7（贴合方案，BPMN/历史/待办真实，推荐）vs 自研轻量审批引擎（更快更可控，材料需标注简化）。
- **Q3 软著材料**：是否需要 M5（60 页源码 + 60 页手册 + 申请表）？推荐一期先交付可运行 Demo + 文档，后续可追加。
- **Q4 范围与角色**：一期按方案 §1.2 七项全做、二期全部不做；角色 6 个（系统管理员 / 内控管理员 / 部门负责人 / 普通员工 / 审计员 / 管理层），是否调整？
- **Q5 仓库与数据库**：远端私有仓库地址（同名 `icp-collab-platform`）；数据库默认用项目内 3307 独立实例（无需现有 root 密码），如需使用现有 3306 请提供账号密码。
