## 6. 偏差与决策（已写入 DECISIONS / docs/03）

| 编号 | 内容 |
| --- | --- |
| D27 | 导出由前端 `exportCsv.ts` 生成 CSV（UTF-8 BOM），后端不提供导出接口 |
| D28 | M2b `submit` 仅状态流转并返回 `pendingWorkflow=true`、`flow_instance_id=null`，M2c 接 Flowable 后改为真实发起 |

| 整改证据 | `evidence` 为逗号分隔 String（如 `"4001,4002"`），非数组（docs/03 §4 第 9 条） |
| 风险阈值配置键 | 实际读 `icp.risk.highScore` / `icp.risk.midScore`，种子未写入，取默认 15/8（docs/03 §4 第 3 条、docs/04 §6.4） |
| 矩阵唯一键 | `uk_risk_control(risk_id, control_id)` 不含 deleted 条件，逻辑删除后同组合重建命唯一键（40002/40000），作为已知限制（docs/03 §4 第 10 条） |

## 7. 本阶段发现并修复的问题（记录）

1. **种子权限与 docs/05 不一致**：初版 V2 缺 `policy:delete`、`policy-category:*`、`risk:status/delete`、`control:*`、`matrix:edit/delete/coverage`、`evaluation:*`、`workpaper:*`、`rectify:reject/close` 等 38 个按钮，前端 mock 阶段暴露；已按 docs/05 精确补齐到 143 菜单/385 授权（V15 同步）。
2. **ADMIN 对内控写权限越界**：补齐后误给 ADMIN 全部 icp 写权限（与三权分立冲突）；已撤回 40 行，ADMIN 对内控严格只读（POST 403/40300 实测），写权限归 ICP_MANAGER。
3. **整改证据类型**：前端按 docs 数组提交报 40000 JSON 解析错；已改为前端 `join(',')` 发送字符串并在 api 层兼容。
4. **Lead 独立探针脚本问题（非产品缺陷）**：`$pid` 只读变量、`$u:` 插值、分类 id 误用 1（实际 1001/1201）、整改响应键 `rectifyId`；已修正，脚本 43/43 ×2。
5. **前端 CRUD 首跑服务端偶发 500**（脏库/重启窗口）：重跑稳定；最终以干净种子重登 52/52 为准。

## 8. 遗留与已知限制（不阻塞 M2b 验收）

1. 制度 `submit`/评价计划 `submit` 尚未接 Flowable（D28，M2c 接管并消除过渡口径）。
2. 制度版本号：新建默认 V1.0，编辑允许调用方传 version，未实现自动版本链（M3 前评估，不阻塞）。
3. 矩阵唯一键与逻辑删除冲突：同一 risk+control 逻辑删除后无法重建；M2c/M3 可用「恢复原行」语义处理（当前前端预检提示 + 后端 40000/40002）。
4. `icp.risk.highScore/midScore` 未写入种子（用默认值）；如需演示可配，M3 前补种子。
5. 缺陷列表无 `rectifyCode`（仅 `rectifyId`），前端按实际渲染；如需展示编码可在响应中补瞬时字段。
6. 导出仅 CSV（前端生成），Excel/PDF 留 M4 文档/报表阶段。
