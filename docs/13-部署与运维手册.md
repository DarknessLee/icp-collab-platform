## 1. 系统拓扑

```
浏览器
  │  http://<host>:<Nginx/预览端口>
  ▼
前端（Vue3 静态资源，Vite dev 5173 / preview 4173 / Docker 中为 Nginx 80）
  │  /api/** 反向代理（Nginx 或 Vite proxy）
  ▼
后端 Spring Boot 3.3.4（:8080，JWT 鉴权、Flyway、Flowable 7.1.0 内嵌）
  ├── MySQL 8.0（:3307 项目实例 / Docker 内为 mysql:3306）
  ├── 本地附件目录 .runtime/files（Docker 内为 minio 卷，预留 S3/MinIO 接口实现）
  └── 进程内缓存 Caffeine（预留 Redis 接口）
```

- 单租户单实例部署；`tenant_id` 字段已预留，多租户为二期。
- 前后端分离：前端只经 `/api/**` 访问后端，不使用 Cookie 会话（JWT Bearer）。
- 定时任务（5 个 handler）与 SSE 连接均为**进程内**实现，因此后端不能水平多实例部署（否则提醒/调度重复、SSE 只能连到其中一台）。

## 4. 方式一：本机一键启动（Windows，已验证）

### 4.1 首次初始化（只做一次）

```powershell
cd D:\MyCodes\icp-collab-platform
powershell -ExecutionPolicy Bypass -File scripts\mysql-init.ps1   # 初始化项目内 3307 实例（ASCII my.ini，datadir=.runtime\mysql）
```

- 该脚本只用本机 MySQL 8 的二进制，**不启动、不修改系统 MySQL80 服务**。
- 若 3307 已初始化过，脚本幂等跳过。

### 4.2 启动（日常）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start-local.ps1
```

脚本依次完成：MySQL 3307 就绪 → 后端启动并等待 `/actuator/health` UP → 前端构建（缺失时）→ 预览 4173 启动 → 打印访问地址、演示账号与健康状态；重复执行幂等（已在运行则跳过）。

**实测**（本机，2026-11-04）：首次 `16.4s`（MySQL + 后端 health UP + 前端预览 4173）；重复执行 `0.5s`（幂等跳过）。冷启动（全新 datadir + 前端重新构建）`45.9s`。

访问 `http://127.0.0.1:4173` 登录（或只起后端 + `scripts\dev-frontend.ps1` 用 5173 开发模式）。

### 4.3 初始化演示数据

```powershell
powershell -ExecutionPolicy Bypass -File scripts\demo-reset.ps1    # 约 40–45s
```

执行：停后端 → `db-reset`（建库 + Flyway V1–V3 + 种子 + db-validate 15/15）→ 起后端 → `seed-flow`（60 个流程实例 / 40 待办 / 20 催办）。完成后：制度 52（40 种子 + 12 流程演示）/风险 40/缺陷 30/协同任务 80。

### 4.4 停止

```powershell
powershell -ExecutionPolicy Bypass -File scripts\stop-local.ps1              # 停前端预览 + 后端
powershell -ExecutionPolicy Bypass -File scripts\stop-local.ps1 -WithDb      # 同时停 MySQL 3307
```

### 4.5 冷启动验证（交付验收）

- 停止全部服务 → 用全新 datadir 初始化（或按 `docs/16` 记录的冷启动步骤）→ `start-local.ps1` → 登录 `admin` → 校验工作台数字。
- 冷启动耗时与实测结果见 `docs/16-M4-交付验收报告.md`。

> 本机无 Docker，`deploy/` 下文件为**交付件**，语法与配置自洽性经静态检查，但**未在本机实际拉起**。以下步骤供具备 Docker 的环境执行。

### 5.1 交付文件（`deploy/`，11 个）

| 文件 | 作用 |

| `scripts/backup.sh` / `restore.sh` | `mysqldump` + 附件卷打包 / 恢复；保留最近 N 份 |

### 5.2 步骤

```bash
cd deploy
cp .env.example .env          # 修改密码、JWT_SECRET、端口
docker compose build          # 构建 backend / frontend 镜像
docker compose up -d          # 启动 mysql、redis、minio、backend、frontend
docker compose ps             # 等待 backend healthy
curl http://localhost:8080/api/v1/actuator/health   # 或 docker compose exec backend curl -f http://localhost:8080/actuator/health
```

- 服务与端口：`frontend`（Nginx，宿主 `FRONTEND_PORT=8080`，托管 dist 并反代 `/api/`）、`backend`（容器内 8080，宿主 `BACKEND_PORT=8081`）、`mysql`（容器 3306，宿主 `MYSQL_PORT=13307`，utf8mb4）、`redis`（6379）、`minio`（9000/9001）。
- 首次启动：MySQL 空库时后端 Flyway 自动建 42 张业务表 + 种子；Flowable 自动建 ACT_* 39 张；管理员账号来自种子（`admin`）。
- 离线部署：在有网机器 `docker compose build` 后 `docker save` 各镜像 → 目标机 `docker load` → `docker compose up -d`（`deploy/scripts/deploy.sh --offline` 会提示所需镜像名）。
- 常见问题：MySQL 初始化慢导致 backend 重启循环（compose 已配 healthcheck + `depends_on: condition: service_healthy`）；Nginx 404（dist 未构建或 SPA fallback 缺失）；上传 413（Nginx `client_max_body_size 25m`）。
- **未实测声明**：本交付未在 Docker 环境启动验证，验收报告（docs/16）按「交付文件」计；验收场景①的「一键部署」以本机 `start-local` 等价验证（冷启动 45.9s）。

## 8. 备份与恢复

### 8.1 本机脚本

```powershell
powershell -ExecutionPolicy Bypass -File scripts\backup.ps1                       # 备份到 .runtime\backups\<ts>\
powershell -ExecutionPolicy Bypass -File scripts\restore.ps1 -Path .runtime\backups\20261104-120000
```

- `backup.ps1`：`mysqldump --single-transaction icp_platform` + 复制 `.runtime/files` + 生成 `manifest.json`（时间、关键表行数、文件数）。
- `restore.ps1`：停后端 → 重建库并导入 dump → 恢复附件目录 → `db-validate`（15/15）→ 起后端 → 健康检查。

### 8.2 Docker 脚本

`deploy/scripts/backup.sh` 与 `deploy/scripts/restore.sh`：`mysqldump` + MinIO/文件卷打包，保留最近 N 份。

### 8.3 恢复演练结果（本机实测，2026-11-04）

1. `backup.ps1` exit 0 / 1.1s → `db.sql 1.33MB` + 附件 **137 个** + `manifest.json`（sha256 + 关键表行数）。
2. 人为破坏：改名 1 条制度（policy）、删除最大 1 条 `coll_task`、删除 1 个附件文件。
3. `restore.ps1 -Path …` exit 0 / **16.7s** → `db-validate` **15/15 PASS**；policy 恢复为 40、task 恢复为 80、附件回 137 个、被篡改数据消失、health UP。
4. 说明：演示态（含 flow 数据）V15 的精确种子行数不成立，脚本对「仅 V15 失败」给 NOTE 放行，其它校验失败仍 exit 1；干净种子/生产备份为严格 15/15。

## 9. 运维例行

| 频率 | 操作 |
| --- | --- |
| 每日 | 查 `/actuator/health`（应 `UP`，含 db）；查 `.runtime/logs/backend.log` 的 ERROR 行；抽查待办/超时任务 |
| 每周 | 备份并校验备份文件可读；查看审计日志异常（大量 403/登录失败）；磁盘占用（MySQL datadir、files、logs） |
| 每月 | 演练一次恢复；清理过期附件/日志（保留≥30 天）；复核密码策略与账号清单 |
| 演示前 | `scripts\demo-reset.ps1` 回到标准演示态（60/40/20）并确认截图与文档数字一致 |

日志：后端 JSON 控制台输出 + 文件；`traceId`（`X-Trace-Id`）贯穿接口与审计（`sys_oper_log.trace_id`），排障时用 traceId 串起请求—SQL—审计记录。

定时任务：5 个 handler（制度到期、评价任务逾期、协同任务提醒、缺陷超期、公告定时发布），进程内 `@Scheduled` 每 10 分钟扫描，命中写站内消息（type=3）与审计；手动执行入口「系统管理 › 定时任务 › 运行」。

## 10. 故障排查

| 现象 | 排查与处理 |
| --- | --- |
| 3307 起不来 / health 的 db DOWN | 看 `.runtime/logs/` 与 MySQL 错误日志；常见 `ibdata1 must be writable`（进程未退干净）→ 停旧 mysqld 再起；确认 3306 系统服务未被误用 |
| 后端启动报 Flyway checksum mismatch | 不要改已应用的 V1–V3；本地演示库可 `db-reset` 重建；已部署环境用 `flyway repair`（受控操作） |
| 登录 40101 / 40102 | 40101 账号密码错误（5 次后 40102 锁定 15 分钟）；管理员可在用户管理解锁/重置密码 |
| 页面接口 403 | 角色无该权限或数据越权（code 40300）；用「角色授权」核对菜单/按钮，`/logs/oper` 查操作审计 |
| 4173 预览 POST 403 | CORS 未含 4173 → 确认 `app.cors.allowed-origins` 含 `http://127.0.0.1:4173` |
| 附件下载 40400「文件实体已丢失」 | `sys_file.file_path` 与 `.runtime/files` 下实际路径不一致（如目录被改名）；用备份恢复或 `demo-reset` |
| 待办为空但流程已发起 | 当前用户不是候选组办理人；「发起」节点需发起人先确认（设计如此，见 docs/10 §7.1） |
| 消息不实时 | SSE 需 `access_token`（EventSource 不能带 Header）；检查代理是否缓冲响应（Nginx 需 `proxy_buffering off`） |
| 磁盘增长快 | 清理 `.runtime/logs/*.log`、旧备份；附件按需归档 |

## 11. 升级与回滚

1. 升级前：`backup.ps1` + 记录当前 commit（`git rev-parse HEAD`）。
2. 拉取新代码 → 新增 `V4__*.sql`（若结构变更）→ `scripts\build.ps1`（后端 170+ tests、前端 build 必须全绿）。
3. `stop-local.ps1` → 启动（Flyway 自动应用 V4）→ `db-validate` → 冒烟（登录/工作台/一个业务闭环）。
4. 回滚：`git checkout <上一 commit>` → `restore.ps1 -Path <升级前备份>` → 重启；Flyway 已应用的 V4 需在回滚分支中保留（不可删文件），或直接用备份库恢复。

## 12. 安全基线

- 更改 `icp.jwt.secret`（≥32 字节随机）与全部演示账号密码；启用 `sys.password.minLength` ≥8、锁定时长 15 分钟。
- 生产使用 HTTPS（Nginx 终止 TLS）；CORS 白名单只保留实际域名。
- MySQL 使用强密码、仅应用账号可写、最小权限；`root` 禁止远程登录。
- 附件：20MB 上限 + 类型白名单；下载走鉴权（文档可见性 + 借阅）；MinIO 场景用预签名私有桶（二期）。
- 审计：操作/登录/变更日志保留≥180 天；日志哈希链与等保二/三级要求为一期外增强项（见 docs/12 §10）。
- 部署文件中的默认密码仅为本地演示，交付前须替换；`.env`/备份文件不入库。
