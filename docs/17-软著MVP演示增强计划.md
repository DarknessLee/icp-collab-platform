# 17 软著 MVP 演示增强计划（M6）

> 目标：以「软著 MVP 演示」为唯一口径，把一期（M0–M4）与二期规划中**未做**的能力整合成一张清单，按「演示价值 ÷ 成本」排序，选择最低成本的一小组增强项开发。本文是 M6 的范围与验收依据；未列「必做/可选」的条目不进入 M6。

## 1. 背景与现状口径

- 一期（M0–M4）已交付：42 张业务表、179 菜单 / 540 权限行、375 API 用例、170 后端单测、24 E2E 用例、28 张交付截图、16 份文档；方案 §九 6 条验收场景均有实测证据（`docs/16`）。
- `PLAN-MATRIX.md` 模块级能力 33 项：已实现 22 / 部分 1（动态表单只读渲染）/ 暂缓 9 / 不做 1（移动端）。
- 但方案原文与二期规划里仍有**未登记**的缺口：一期 17 项（下文 B 类来源）、演示级限制 7 项，二期 P2-1～P2-4 的平台化/企业级能力。本文件把这些合并为一张表统一处置。
- 软著申请真正需要的是：可运行、可截图、功能面完整、说明书能写满的自洽系统。因此 M6 只补**演示可见**且**复用现有模式**的能力；基础设施、安全加固、不可见项一律不做（记录理由，避免以后重复讨论）。

## 2. 整合清单（一期未做 + 二期未做）与处置

成本单位：单人日（含开发+自测；不含全量回归，回归每个 Wave 一次）。「处置」：必做 W1/W2 进入 M6；可选 W3/W4 视预算；不做/暂缓记录理由。

## 3. M6 范围（最低成本）

### W1 演示可见性（必做，约 2.5 人日）

1. **文档在线预览**（已完成）：文档中心「预览」按钮，PDF/图片内嵌预览，其余格式提示下载；复用 `docApi.download` 的 blob；后端文档列表补 `fileName`/`contentType`（`CollDoc` 瞬时字段 + `DocService.fill`）用于文件名无扩展名时按 MIME 判断。
2. **报表图表下钻**（已完成）：缺陷柱状图（严重程度 × 状态）、风险分布饼图点击 → 跳缺陷/风险列表并带 `severity/status/riskLevel`；任务流程耗时图按 `processKey` 直达流程监控。
3. **列表脱敏**（已完成）：`frontend/src/utils/mask.ts`（`maskMobile` / `maskEmail`），用户管理列表手机号、邮箱掩码（`138****8000`），仅展示层，不改库。
4. **流程抄送**（已完成）：同意/驳回弹窗可选抄送人（`ccUserIds`）→ 落 `coll_message`（biz_type=CC）；消息中心增加「流程抄送」业务筛选，无需新菜单。
5. **导出扩面**（暂缓）：风险、控制矩阵、公告、日志增 CSV 导出（复用 `utils/exportCsv.ts`）；演示价值低，留待 W2 后评估。

### W2 流程技术深度（必做，约 1.5 人日）

6. **条件分支 + 两级审批**：采购申请按金额分级——`amount <= 5000` 仅部门负责人；`amount > 5000` 追加管理层审批；BPMN 加 `exclusiveGateway` + `conditionExpression`，演示历史时间线可见两级。失败回退：保持原单级流程可用。

### W3 模块补齐（可选，约 3.5 人日）

7. **会议纪要**：新表 `coll_meeting`（会议主题/时间/地点/参会人/纪要正文/附件）+ 页面 + 菜单 + 权限 + 种子 15 条（需 Flyway V4）。
8. **数据大屏**：全屏看板页（6–8 图 + 轮播 + 时间），复用 dashboard/report 接口。

### W4 业务广度（可选，约 3 人日）

9. **合同管理**：合同台账（相对方/金额/起止/状态）+ 到期提醒 + 合同审批流（新表 + 菜单 + 流程 + 预警联动）。

**全量 M6 = 10.5 人日；最低成本交付（W1+W2）= 4 人日。**

## 4. 验收方式（每个 Wave 一次）

- 构建：后端 `mvn -B clean verify` 零失败；前端 `scripts\build-frontend.ps1` 零错误。
- API：`scripts\test-api*.ps1` 新增/更新用例全绿；新增接口写入 `docs/03-接口契约`。
- UI：E2E 增 spec（预览/下钻/抄送/两级审批各 ≥1 用例），`scripts\test-e2e.ps1` 全绿。
- 截图：受影响页面重出（`E2E_DEMO=1` + `screenshots.spec.ts`），`docs/screenshots/INDEX.md` 同步。
- 文档：`docs/05` 权限、`docs/09`/`docs/10` 对应章节、本文勾选进度、`PLAN-MATRIX` 状态。
- 状态：`scripts\demo-reset.ps1` 后手验演示态；`check-docs.ps1` PASS；提交+推送+回填 hash。

## 5. 成本控制约定

- W1/W2 **不加新表、不加新菜单**（复用现有页面/接口/权限），避免种子、菜单授权、权限矩阵的联动成本。
- 只有 W3/W4 才引入 Flyway V4（新表/菜单/权限/种子），并按一期流程补 `docs/04` 数据字典与截图。
- 不在 M6 启动智能体团队：单 Agent 串行，压缩上下文、日志只留尾部，回归每个 Wave 一次。
- 每个 Wave 完成即提交并推送，可单独回滚；任一 Wave 失败不影响已交付一期。

## 6. 决策与待确认

- 已定：M6 = 演示增强，不改一期已交付范围与结论；不做项在 §2「处置」列留档（暂缓/不做），避免重复讨论。
- 待用户确认：① W3（会议纪要/大屏）是否做；② W4（合同管理）是否做；③ M5 软著材料何时启动；④ 演示是否需要录屏/说明书成稿（可由 docs/14 扩写）。
