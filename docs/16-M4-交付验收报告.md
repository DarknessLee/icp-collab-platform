## 7. M4 期间发现并修复的问题

1. 种子文案业务化时误改 `sys_file.file_path` 前缀（`seed/`→`seed/`），导致文档下载返回 40400 → 恢复前缀、重生成 V2、`flyway:repair` + `validate` 通过；test-api m2d 恢复 109/0。
2. `verify.ps1` 的 fail-fast 失效（子脚本输出被函数返回值捕获，`$ok` 变成数组仍打印 PASS）→ 改为 `| Out-Host` 并用 `$LASTEXITCODE` 判定。
3. `stop-local.ps1 -WithDb` 拆除失败：`mysqladmin shutdown` 竞态 + PS 5.1 函数必须先定义后调用 → 函数前置、shutdown 重试、仅对本项目 `my.ini/datadir` 的 mysqld 兜底 `taskkill`，连续两次 exit 0。
4. 全库测试文本清理（`M1 seed`/`M2c seed`/`seed-XX` 等）→ 业务化文案，截图与验收报告同步重出。
5. 截图横向滚动残留（点击链接导致表格左移）→ 截图脚本统一 `window.scrollTo(0,0)` + 容器 `scrollLeft=0`。

## 8. 遗留与限制

1. Compose 一键部署需在具备 Docker 的环境按 `deploy/README.md` 实测（本机不可用）。
2. SSE 与在线会话为单实例内存实现，多实例需换 Redis 广播/共享会话（二期）。
3. 自定义数据范围（`data_scope=5`）为二期；一期为本人 / 本部门 / 本部门及下级 / 全部。
4. BPMN 为固化 6 条流程（一级审批 + 发起确认），在线设计器、加签/转办/委托为二期。
5. 文档中心在线预览（PDF/Office 渲染）为二期，当前为下载 + 元数据预览条目。
6. 示例数据为虚构企业，重启用 `reset-data` 即可恢复（不依赖手工清理）。
